1. Executive Summary & Fleet Consolidation

Prior to WinCraft, Windows host inspection, file-lock debugging, duplicate file reclamation, and service administration were split across five separate Python MCP servers plus a prototype Python scaffold. Running multiple Python virtual environments and background webservers merely to inspect processes or check which process locked a file consumed hundreds of megabytes of RAM.

One Native Binary, Three Surfaces: WinCraft compiles to a single pure-Rust workspace (wincraft-core, wincraft-mcp, wincraft-app) with zero runtime dependencies, zero network port claims, and strict compile-time denial of unwrap, expect, panic, todo, and unimplemented.

2. Flagship Subsystems

🔒 Native Win32 Restart Manager Lock Inspector

When Windows refuses to delete or overwrite a file or directory, win_lock_inspect links directly against rstrtmgr.dll (RmStartSession, RmRegisterResources, RmGetList) to report the exact locking PID, application name, and service short name—with zero EULA prompts or kernel drivers.

🧬 3-Stage Streaming Duplicate Detector

win_fs_dups scans directory trees at native speed by (1) grouping files by exact byte size, (2) hashing only the first 4 KB of size-colliding files, and (3) streaming 64 KB chunks through a zero-dependency FIPS 180-4 SHA-256 engine only for prefix matches.

🧹 RAM Weeder & Protected Process Guard

win_weeder_scan identifies forgotten Rust test executables, orphaned headless browsers, and runaway workers. win_weeder_reap requires confirm=true and enforces an immutable allowlist protecting csrss.exe, lsass.exe, svchost.exe, explorer.exe, nssm.exe, pwsh.exe, and IDE hosts.

🔌 Fleet-Correlated Port Mapper

win_port_map maps listening TCP/UDP sockets to owning PIDs and automatically cross-references mcp-central-docs/operations/WEBAPP_PORTS.md so fleet services are badged by name in both the CLI and L3 desktop app.

3. Universal Cards / List / JSON Engine & Multi-Format Export

Every dataset in WinCraft (processes, services, ports, disks, weeder candidates, fileops items/duplicates/grep matches, locks, startup, tasks, registry, and tools) flows through wincraft_core::export:

  • Switchable Views (Default: Cards): Toggle instantaneously between 🗂 Cards (Default) (with visual capacity/memory bars and one-click action buttons), ☰ List / Table, and { } JSON.
  • Live Substring Filtering & Numeric-Aware Sorting: Filter across all columns in real time and sort any column ascending or descending with automatic numeric detection (PID, MB, GB, %, Port).
  • Full Pagination: Choose 10, 25, 50, or 100 items per page with First, Prev, Page X / Y, Next, and Last navigation.
  • One-Click & CLI Export: Export any filtered, sorted view to CSV, MD (Markdown Table), TXT, or JSON.
# Default Cards view (paginated, 5 items per page)
wincraft proc-list --page-size 5

# List/Table view sorted by Display Name (col 1)
wincraft svc-list --format list --sort-col 1 --page-size 15

# Markdown table output + simultaneous CSV export
wincraft disk-list --format md --export D:\Dev\repos\wincraft\exports\disks.csv

5. Defense-in-Depth Safety Invariants

Five Non-Bypassable Guards Enforced in wincraft-core:
  1. Explicit Confirmation Gate: Every mutating verb (weeder_reap, fs_backup_write, fs_undo_backup, fs_archive_create, svc_control, reg_write) refuses execution unless confirm: true is explicitly supplied.
  2. Global Read-Only Lock: Passing --read-only, setting WINCRAFT_READ_ONLY=1, or toggling the UI Read-Only Guard blocks all mutating commands across CLI, MCP, and GUI.
  3. Mandatory Pre-Write Backups: fs_backup_write creates a timestamped .bak sibling before modifying any existing file; reg_write exports a timestamped .reg snapshot to %LOCALAPPDATA%\wincraft\backups\ before touching HKCU.
  4. Protected Process Allowlist: Critical Windows and developer host processes (csrss.exe, lsass.exe, svchost.exe, explorer.exe, nssm.exe, pwsh.exe, code.exe, claude.exe) can never be reaped.
  5. NSSM Service Discipline: svc_control inspects sc.exe qc for NSSM wrappers and strictly uses sc.exe stop / sc.exe start rather than killing child processes.
